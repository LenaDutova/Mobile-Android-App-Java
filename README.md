# Хранение данных в базе данных SQLite с помощью ORM ROOM
Если данные приложения подвержены изменениям, имеют сложные взаимосвязи, но главное их объемы значительны, то следует реализовывать хранение в базе данных. Реляционная СУБД SQLite уже интегрирована в мобильную операционную систему и для ее использования не требуется интеграция вспомогательных библиотек. Но для упрощения работы с базой данных можно подключить рекомендованную разработчиком ORM-библиотеку (Object-Relational Mapping) ROOM, которая возьмет на себя ряд общих действий - осуществление запросов к базе данных, преобразования данных к объектам предметной области и пр.

## Подключение зависимостей
Для подключения ORM ROOM необходимо добавить зависимости:
```
implementation("androidx.room:room-runtime:2.8.4")
annotationProcessor("androidx.room:room-compiler:2.8.4")
```

Так как обращения к базе данных могут занимать значительное время (в связи с объемами предоставляемых данных), то их необходимо производить вне главного (UI) потока исполнения (например вынести в область IO). Для переключения между потоками можно использовать фреймворк RxJava:
```
implementation("io.reactivex.rxjava3:rxandroid:3.0.2")
implementation(@androidx.room:room-rxjava3:2.8.4")
```

## Описание сущеностей базы данных
Сущности базы данных транслируются в простой POJO-объект с публичными полями или публичным коструктором и сеттерами, который обязан иметь аннотацию @Entity и один из атрибутов с аннотацией @PrimaryKey. Обычно ROOM может транслировать "созвучные" имена столбцов базы данных и ваших атрибутов, но через аннотацию @ColumnInfo (для столбцов) или внутри @Entity (для таблицы в целом) можно задать явные значения:
```
@Entity (tableName = "jokes")
public class Joke{
  @PrimaryKey
  int id;
  @ColumnInfo(name = "single")
  boolean isSingle;
}
```

В качестве типов данных атрибутов используются либо базывые типы данных, либо иные сущности (что позволяет моделировать предметную область со сложными отношениями).

## Создание DAO для сущностей
DAO-интерфейсы (Data Access Object) в данном случае описывают все возможные обращения к определенной таблице. Его необходимо пометить аннотацией @Dao.

Многие запросы легко генерируется через ROOM (создание - @Insert, удаление - @Delete, обновление - @Update). Более сложных запросы осуществляются через @Query с уточнением SQL-запроса, в который также можно также передавать параметры (место инъекции в SQL-запросе обозначается двоиточием):
```
@Dao
public interface JokesDAO {
    @Query("SELECT * FROM jokes")
    Flowable<List<Joke>> getAll();

    @Query("SELECT * FROM jokes WHERE id = :jokeId")
    Single<Joke> getJoke(int jokeId);
}
```

## Создание объекта соединения с базой данных
Когда сущности были созданы, dao-интерфейсы объявлены необходимо создать абстрактный класс, наследуемый от RoomDatabase, который будет описывать структуру базы данных и текущую версию (внутри аннотации @Database), а также возвращать ссылки на сгенерированные реализации DAO-классов для указанных сущностей:
```
@Database(entities = {Joke.class}, version = 1)
public abstract class MobileDatabase extends RoomDatabase {
    public abstract JokesDAO jokesDAO();
}
```

Также можно добавить классы, содержащие логику @TypeConverter для преобразования специфических типов в базе данных к типам определенным в cущностях (например, если дата хранится текстом, а не объектом timestampt)

## Открытие соединения 
Для открытия соединения потребуется контекст (деятельности, фрагмента, сервиса или самого приложения). На открытом соединении можно получать экземпляры DAO-классов и уже с их помощью обращаться и исполнять те или иные запросы: 
```
db = Room.databaseBuilder(context, MobileDatabase.class, "DB").build();
db.jokesDAO().getAll();
```

## RxJava
ReactiveX - это набор библиотек для реактивного программирования, который упрощает работу с асинхронными операциями, такими как события или потоки данных. По сути, это способ работать с данными, которые появляются не сразу, а потоком, и вы можете обрабатывать их, как только они появляются, с помощью удобных операций. Но более того для языка java и что важнее мобильной операционной системы android предусмотрены отдельные версии, позволяющие также переключаться между потоками исполнения. Хотя RxJava проигрывает kotlin с его корутинами по простоте синтаксиса.

Концепт RxJava строится на наличии:
- источников данных (например Flowable, Single, Completable), подбираемых относительно потока и формата данных (возможны ли ошибки, определен ли предел данных и пр.),
- операторов над данными, которые производят преобразования "на лету", с помощью которых можно фильтровать получаемые значения (filter), преобразовывать их из одного типа в другой (map), изменять текущий поток (flatMap) или объединять несколько потоков данных (merge), например данные из сети и базы данных,
- и слушателях (CompositeDisposable), которые подписываются (subscribe) на эти источники данных (перед закрытием приложения, требуется "отписаться").

Также можно производить переключение того, в каком потоке будет происходить та или иная операция над данными в методах subscribeOn(источник данных) и observeOn (подписка и все последующие за ней операции):
```
Single.just("Go:")
  .map(s -> s.concat(Thread.currentThread().getName() + ":"))
  .subscribeOn(Schedulers.io())
  .observeOn(AndroidSchedulers.mainThread())
  .subscribe (s -> Log.d("DEBUG", s + Thread.currentThread().getName()));
```
